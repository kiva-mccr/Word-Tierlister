# `src/app.py`

The main window (`App`): the header, the three placing views, the duel tabs, the chart and shelf, the definitions pane, the bottom bar, keys, zoom and window fitting, undo, and the background jobs it polls.

- **Uses:** `browser`, `constants`, `dealing`, `definitions`, `deps`, `errors`, `filepicker`, `fonts`, `framesync`, `fullscreen`, `keymap`, `review`, `rudeness`, `saves`, `shortcuts`, `sizing`, `smooth`, `sources`, `standalone`, `syncdialog`, `theme`, `tiercolours`, `ui_chart`, `ui_motion`, `ui_style`, `widgets`, `wordsource`
- **Used by:** `speed_check`, `stress_ui`, `tierlist`
- **Tests:** `_selftest_build`, `_selftest_defsize`, `_selftest_devtools`, `_selftest_filepicker`, `_selftest_framesync`, `_selftest_fullscreen`, `_selftest_looks`, `_selftest_lookup`, `_selftest_release`, `_selftest_sizing`, `_selftest_sources`, `_selftest_tabswitch`, `_selftest_ui`, `_selftest_ui2`, `_selftest_veil`, `_selftest_zoom`

The module docstring has the details; this page is the map.

## Rules and pitfalls (fixed before: keep them fixed)

- DT-5: Tune & reroll rerolls only once the tuner printed "Done" (`job["tuned"]`) and its process has ended (Keep or Discard closed it): a tuner closed while tuning (Discard) or failing makes no new words. `_watch_tuner` (Tk side) clears `_tuner_job`; `dev_progress` only reads it and treats an ended process as not running.
- F-53: a maximize or restore slides the page's contents (`_slide_from_here`) from where the old picture was left (moved by half the change: framesync's centre gravity, X11 only) in a straight line to their place. The slide starts only once the window and the page have the new size (restored: the size before maximizing, `_normal_size`; some window managers pass through the maximized width first): its first frames aimed at the old page, then turned, and it looked like a loop. `_recenter` leaves a sliding `inner` alone.
- `_apply_grow` does nothing once `reopening` is set: the shared fonts already belong to the new window and the old window's own are gone, so measuring its labels raised "named font font4 does not already exist" (seen on GitHub's Windows, a grow job left over from leaving full screen).
- FS-2: full screen is `full_var` (meta full_screen); `_apply_full_screen` swaps the four menus for `menu_btn` and sets `StyledDialog.decorate` (the Back bar) only while it is on. Esc opens the pause menu through the keymap's "menu" action, so comparing's own Esc (stop) still wins. A new look picked in the pause menu opens it again on the same page (`take_over`). `sizing.is_maximized` counts full screen as maximized (its zoom).
- `_follow_tuner` keeps reading the tuner's stdout after it says Done (its window stays open for Keep): a pipe nobody reads fills and freezes the tuner. The tuner's prints go through `say`, which never raises once the program has closed.
- A developer bubble that opens a window of its own (the review, the crash test) closes its dialog first: a StyledDialog holds the input (grab), so the review opened under it could not be clicked.
- `_fit_big_text`: a duel text with a space shrinks to about a third and then wraps; one long word cannot wrap, so it shrinks as far as it must (7 pt at least): on a Mac pneumonoultramicroscopicsilicovolcanoconiosis ran past the window. The sizing test puts it in every duel.
- A new look (`reopen_while_asked`) builds a second Tk while the old one is up; Tk's event loop runs while any main window is left, so `_drop_old` always destroys the old root, even when its `_shut` fails part-way (a window left over keeps the program from ending after the last one closes). The looks test traces each window built and closed. Tk's event loop forgets a quit asked before it starts: a new look asked again while the new window was still opening (`open_window` runs events; on a Mac long enough) waited for good, so `reopen_while_asked` builds again at once when `reopening` is already set and cancels the quit still waiting (`_quit_job`), or it would end the next window's loop.
- A zoom out never shows anything bigger than before (`_fit_at_most`): on a Mac the fit from the new zoom found room with the definitions pane open that the pane's opening fit had not, and zooming out made the text bigger.
- Tk draws every layout the fit measures (`update_idletasks`), so a fit must never try sizes on screen one by one (F-41: switching tabs with the definitions pane open, the pane was tried a line at a time and the page stuttered; the duel cards blinked out). The pane's lines are worked out from one measurement (`_pane_lines`, `DefinitionDrawer.height_for`), and it is pinned while they change (`DefinitionDrawer.pin`).
- From one duel tab to another the cards fade over to the new pair (`_fade_duel` -> `DuelCards.show(fade=True)`, under the duel's `anim_key`: a key press or a tab switch finishes it); the big text is sized for the new words when they show (`then=`).
- Never try a zoom on screen to see if it fits when it can be known before: `_precheck_zoom` tries the steps while the window is hidden (`open_window`) and `_remember_cap` keeps the limits in the save per screen and version (F-30; meta zoom_limits, one per screen since Z-1). Estimating from the page's size failed: it grows 0.5-1.7x as fast as its text.
- The page keeps room for a one-line message under its contents (`_toast_room`, F-29/UI-72) inside its breathing room (max, not sum: a sum cost the laptop its 110%); `_recenter` keeps the contents above it.
- A fit that changes an open definitions pane's height eases it (`_fit_window` wraps `_fit_size`; F-29); tests that check the settled layout finish animations first.
- A timer that reads the save checks it is still open (`App.shut`, `Store.closed`): the form offer's fired after closing and failed reading the closed save (F-25).
- Turning censoring on from View says it may not be fully accurate in a short toast (U-2, asked for: the same words as How words are dealt's line, never a longer note; never a window of its own, UI-71).
- Z-1 (asked for: nothing on the page resizes the window or its text): the fit measures the worst case, never the view on screen (`_worst_size`: the tallest place view, comparing; a duel with its drop-down, a two-line context and two long words at 7 pt; room for a message; the pane at `DEF_LINES_MIN` whether open or not). It runs only at opening, on a zoom, on maximize / restore, on another monitor and when a grown window goes back to normal. A tab, the pane, a comparison or a definition only call `_fill_pane` (the pane takes the room the view leaves, eased). Never call `_fit_window` for a layout change: that is how the window grew and the text shrank before. `_fill_pane` re-fits once only when even the shortest pane does not fit (something `_worst_size` misses: add it there).
- The grown window (UI-25) is checked against the worst case too (`_apply_grow` steps down until `_worst_size` fits): the page grows faster than its text.
- Each monitor keeps its own zooms (`_zoom_meta` / `_set_zoom_meta`, meta `monitor_zooms`, keyed by `_monitor_id`; "zoom" keeps the last chosen; an older save's "zoom_max" is no longer read, where a new monitor starts). `_check_monitor` runs `MONITOR_PAUSE_MS` after the window stops moving. A fit only moves the window when it changed its size (never a window being dragged), and shrinks it only to the monitor's usable area.
- Window size: what shows = min(zoom, biggest that fits) x grow; measure minimum sizes at grow 1 (`_fit_window`).
- A window grown by its minimum size alone gets that size set too (`_fit_size`): left to the minimum, it shrank back when the minimum fell. Before it shows, its size is the one asked for (`_window_size`: winfo_* say 1 there). The centre contents are placed by their top (`_recenter`, also on their own `<Configure>`): centred by Tk plus an offset, two roundings shook them by a pixel.
- Every key goes through `on_key` and the keymap; a held key repeats after 500 ms, then every 250 ms (`_repeat_allowed`).
- Messages: `flash(text, kind)`; each is its own toast, newest on top. Text-only places name a censored word with `shown()` (masked); everything drawn smears it.
- The window opens complete (`open_window`, F-1).
- It stays see-through after opening until nothing has resized or moved it for `SETTLE_MS` (`_unveil`, at most `VEIL_MAX_MS`; F-48, asked for): GNOME maximizes a new window that nearly fills the screen just after it shows, and the re-fit that follows was seen as a resize "test". While see-through, `_on_root_configure` runs the grow and the monitor check after 20 ms instead of 80 / 300.
- A fit never starts above the limit `_precheck_zoom` found for this screen (`_fit_size` reads `_zoom_cap`; F-48): a zoom (then UI-57's maximized one) this screen cannot fit tried each size on screen from that zoom down.
- A maximize or restore keeps the text the size it shows (F-52, asked for, replacing UI-57's own zoom for the maximized window and F-50's see-through re-fit: re-fitting at a new text size took ~0.2 s and jarred however it was hidden). `_on_root_configure` lays the page out at once, inside that `<Configure>` (`_note_maximize` notes the change; `_apply_grow` then only recentres and fills the pane, also while maximized): an idle job came after Tk's own redraw (F-49). The size comes from the event (`_size_now`, read by `_window_size`): `update_idletasks` there would draw. Other resizes keep the 80 ms pause and grow the contents (UI-25). On GNOME the stretching while maximizing is its own animation.
- The first start offers the other form once (`_offer_other_form`, T-9), never while a dialog is open (`widgets.dialog_open`), a job runs or a download is going; `App(offer_form=...)` is off unless `main()` turns it on, so tests never see it.
- Every word in a message goes through `shown()` (duel results too: they once printed censored words whole).
- `on_close` waits while `busy` (a worker writing the save) and cancels pending timers before destroying the window.
- The fit may shrink a big zoom to half the normal size on a small screen (`FIT_LOWEST` applies to the normal size, not the zoom).
- One zoom (F-52; UI-57's `zoom_max` is gone). A fit never moves or resizes a maximized window (it would un-maximize). A zoom step is "in" only when it is bigger than zoom x grow (in a grown window 120% can be a step down: it was refused as "as big as fits").
- on_close cancels pending `after` jobs with Tcl's `after cancel`, never `after_cancel` (that deletes a command another widget still owns; root.destroy then raises "can't delete Tcl command").

## Changing it

- Building the window: `_build_ui` / `_build_header`. Placing / skipping: `place_word` / `skip_word`. Zoom: `set_zoom` / `zoom_step`.
- A word looked up on the card (UI-51) is tidied by `constants.typed_word`, needs a letter or a number, and is added in lower case. Undoing its placement or skip brings it back onto the card (`_was_looked_up`); Undo ends typing first (F-16).
- Turning censoring on calls `censor_note` (UI-64, U-2): a toast, never a dialog that waits (a modal one hung the tests and would block the How words are dealt page it opens over).
- Updates (U-1): `_check_for_update` runs only on main's starts (`offer_form`), at most once a day, and tells a version once; `_after_update` says an update happened once (meta `updated_from`, set by sources before the restart).
- A new look (UI-66): `reopen` ends the event loop with `after(0, quit)` (a quit asked before the loop runs is forgotten: the loop never ended), `reopen_while_asked` builds the new window while the old one is still up and sets `tk._default_root` to it (anything made without a master must not land on the old one), `take_over` copies place, size, maximized state, the looked-up word and Browse, and `_drop_old` closes the old one after it shows (also from `_shut`, so it never lingers).
